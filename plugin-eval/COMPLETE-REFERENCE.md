## Architecture Overview

```
AI-SSDLC Project
├── plugin/                    ← THE PLUGIN (source code)
│   ├── plugin.json           ← Plugin manifest
│   ├── package.json          ← Dependencies
│   ├── src/                  ← Plugin implementation
│   ├── tests/                ← Plugin unit tests
│   └── dist/                 ← Compiled output
│
└── plugin-eval/              ← THE TEST INFRASTRUCTURE
    ├── eval.config.json      ← Eval configuration
    ├── suites/               ← Test definitions
    ├── fixtures/             ← Test data
    ├── reports/              ← Test results
    └── *.md                  ← Documentation
```

**Key Distinction:**

| Aspect | `plugin/` | `plugin-eval/` |
|--------|-----------|----------------|
| **Purpose** | Contains the Claude plugin itself | Tests the plugin |
| **What's here** | Source code, compiled code | Test cases, configs, results |
| **Users** | Plugin developers | QA engineers, CI/CD |
| **Ownership** | Application code | Quality assurance |
| **Dependencies** | Claude plugin SDK | Eval framework |

## Folder Structure & Purpose

```
plugin/
├── plugin.json              ← Manifest (tool definitions, metadata)
├── package.json             ← Node.js dependencies & build config
├── src/                     ← TypeScript source code
│   ├── index.ts            ← Main entry point (exported functions)
│   ├── tools/              ← Tool implementations
│   │   ├── threat-model-generator.ts
│   │   └── security-assessment.ts
│   ├── types/              ← TypeScript interfaces
│   ├── utils/              ← Helper functions
│   └── config.ts           ← Configuration
│
├── tests/                   ← Plugin unit tests (Jest)
│   ├── threat-model-generator.test.ts
│   ├── security-assessment.test.ts
│   └── integration.test.ts
│
└── dist/                    ← Compiled JavaScript (generated by npm run build)
    ├── index.js
    ├── tools/
    └── types/
```

#### `plugin.json` — Plugin Manifest

Declares what the plugin does and what tools it provides:

```json
{
  "name": "ai-ssdlc-plugin",
  "version": "1.0.0",
  "description": "Claude plugin for SSDLC assistance",
  "entry_point": "src/index.ts",
  "capabilities": [
    "threat-modeling",
    "security-assessment"
  ],
  "tools": [
    {
      "name": "threat_model_generator",
      "description": "Generate STRIDE threat models",
      "input_schema": {
        "type": "object",
        "properties": {
          "system_description": { "type": "string" },
          "scope": { "type": "string", "enum": ["component", "layer", "full-system"] }
        }
      }
    }
  ]
}
```

**What it defines:**
- ✅ Tool names (what the eval framework calls)
- ✅ Input schemas (what data each tool expects)
- ✅ Plugin metadata (version, description)
- ✅ Entry point (where the plugin code starts)

#### `package.json` — Dependencies & Build Scripts

Specifies Node.js dependencies and how to build:

```json
{
  "name": "ai-ssdlc-plugin",
  "version": "1.0.0",
  "main": "dist/index.js",
  "types": "dist/index.d.ts",
  "scripts": {
    "build": "tsc",
    "dev": "tsc --watch",
    "test": "jest",
    "lint": "eslint src/",
    "format": "prettier --write src/"
  },
  "dependencies": {
    "@anthropic-ai/plugin-sdk": "^1.0.0"
  },
  "devDependencies": {
    "typescript": "^5.0.0",
    "jest": "^29.5.0"
  }
}
```

**Build scripts:**
```bash
npm install          # Install dependencies
npm run build        # Compile TypeScript → JavaScript
npm run dev         # Watch mode (rebuild on change)
npm test            # Run unit tests
npm run lint        # Check code style
npm run format      # Auto-format code
```

#### `src/` — Plugin Source Code

**Example: `src/index.ts`**

```typescript
/**
 * Plugin entry point
 * Exports all tool functions that plugin-eval calls
 */

import { ThreatModelGenerator } from './tools/threat-model-generator';

export async function generateThreatModel(input: {
  system_description: string;
  scope: 'component' | 'layer' | 'full-system';
}): Promise<{
  status: string;
  threats: Array<{
    id: string;
    category: string;
    description: string;
    mitigation: string;
  }>;
}> {
  const generator = new ThreatModelGenerator();
  return generator.generate(input.system_description, input.scope);
}

export async function assessSecurity(input: {
  architecture_doc: string;
  framework: 'NIST' | 'ISO27001' | 'PCI-DSS' | 'GDPR';
}): Promise<{
  status: string;
  compliance_percentage: number;
  gaps: Array<{ control_id: string; description: string }>;
}> {
  // Implementation
}
```

**Key points:**
- Functions are **exported** — plugin-eval calls them by name
- TypeScript allows type safety
- Returns **structured data** (JSON-serializable)

#### `tests/` — Plugin Unit Tests

```typescript
// tests/threat-model-generator.test.ts
import { generateThreatModel } from '../src/index';

describe('Threat Model Generator', () => {
  it('should generate threats for a component', async () => {
    const result = await generateThreatModel({
      system_description: 'REST API with JWT auth',
      scope: 'component'
    });
    
    expect(result.status).toBe('success');
    expect(result.threats.length).toBeGreaterThan(0);
    expect(result.threats[0]).toHaveProperty('category');
  });
});
```

**Run tests:**
```bash
npm test                    # Run all tests
npm test -- --watch        # Watch mode
npm test -- --coverage     # Coverage report
```

#### `eval.config.json` — Eval Configuration

Controls how tests run:

```json
{
  "version": "1.0.0",
  "plugin_path": "../plugin",                    // Where the plugin is
  "test_suites": [                               // Which suites to run
    "suites/basic.json",
    "suites/threat-modeling.json",
    "suites/security-assessment.json",
    "suites/layer-threat-models.json"
  ],
  "sandbox": {
    "timeout": 15000,                           // 15 seconds per test
    "max_retries": 2,                           // Retry failed tests twice
    "environment": "test"
  },
  "reporting": {
    "format": "json",                           // Output format
    "output_dir": "reports",                    // Where to save results
    "generate_html": true,                      // Also generate HTML
    "fail_threshold": 0.8                       // 80% pass rate = success
  },
  "ci": {
    "enabled": true,                            // CI/CD mode
    "fail_on_warning": false,
    "publish_results": true
  }
}
```

#### `suites/` — Test Suite Files

Each suite is a JSON file with test case definitions:

```json
{
  "name": "Test Suite Name",
  "version": "1.0.0",
  "description": "What this suite validates",
  "test_cases": [
    {
      "id": "test-001",                         // Unique ID
      "name": "Test name",
      "description": "What it tests",
      "tool": "threat_model_generator",         // Which plugin tool to call
      "input": {                                // What to pass to the tool
        "system_description": "REST API with auth",
        "scope": "component"
      },
      "expected_output": {                      // What we expect back
        "status": "success"
      },
      "assertions": [                           // Validation rules
        {
          "path": "$.threats",
          "operator": "length_gte",
          "value": 3
        }
      ],
      "timeout": 15000,
      "retry_count": 1
    }
  ]
}
```

#### `fixtures/` — Test Data (Optional)

Store reusable test data to avoid repetition:

```
fixtures/
├── architectures/
│   ├── simple-api.md         # "REST API with JWT auth..."
│   ├── microservices.md      # "Multi-service system..."
│   └── three-tier-app.md     # "Angular + Spring Boot + SQL Server..."
│
├── responses/
│   ├── expected-threats.json # Expected threat model output
│   └── expected-compliance.json
│
└── edge-cases/
    ├── empty-input.json      # Should error gracefully
    └── extreme-scale.md      # 10,000+ component system
```

**Reference fixtures in tests:**

Instead of:
```json
"input": {
  "system_description": "REST API with JWT authentication, Spring Security, rate limiting..."
}
```

Use:
```json
"input": {
  "@fixture": "fixtures/architectures/simple-api.md"
}
```

## Core Files Explained

### Comparison: `plugin.json` vs Files in `plugin-eval/`

| File | Location | Purpose | Content |
|------|----------|---------|---------|
| **plugin.json** | `plugin/` | Declare what the plugin does | Tool names, input schemas, capabilities |
| **eval.config.json** | `plugin-eval/` | Configure how tests run | Timeouts, retry logic, reporting |
| **suites/*.json** | `plugin-eval/suites/` | Define test cases | Test inputs, expected outputs, assertions |

**Example workflow:**

```
plugin.json defines:
  ├─ Tool: "threat_model_generator"
  ├─ Input schema: { system_description, scope }
  └─ Output: { status, threats[] }
       ↓
suites/basic.json calls it:
  ├─ Input: { "REST API", "component" }
  ├─ Expected: { "status": "success", "threats": [...] }
  └─ Assertions: threats.length >= 3
       ↓
eval.config.json controls it:
  ├─ Timeout: 15000ms
  ├─ Retries: 2
  └─ Report: JSON + HTML
```

## Basic Commands

### Installation & Setup

```bash
# 1. Install plugin dependencies
cd plugin
npm install
cd ..

# 2. Build the plugin
cd plugin
npm run build
cd ..

# 3. Verify the build worked
ls -la plugin/dist/index.js  # Should exist
```

### Running Tests

```bash
cd plugin-eval

# Run ALL test suites
npx claude plugin eval run --config eval.config.json

# Run specific suite
npx claude plugin eval run --config eval.config.json --suite suites/basic.json
npx claude plugin eval run --config eval.config.json --suite suites/layer-threat-models.json

# Run with custom timeout
npx claude plugin eval run --config eval.config.json --timeout 30000

# Run with debugging output
npx claude plugin eval run --config eval.config.json --debug

# Validate configuration (don't run tests)
npx claude plugin eval validate --config eval.config.json

# Dry run (check syntax, don't execute)
npx claude plugin eval run --config eval.config.json --dry-run
```

### Testing the Plugin Directly

## Test Suite Management

### Understanding Test Suites

Each suite in `suites/` is independent:

```
suites/
├── basic.json                    ← Fast validation (10 sec)
├── threat-modeling.json          ← Domain-specific (45 sec)
├── security-assessment.json      ← Compliance checks (40 sec)
├── layer-threat-models.json      ← Per-layer validation (60 sec)
└── layer-compliance-assessments.json ← Per-layer compliance (90 sec)
```

### Adding a New Test Case

**Step 1: Edit the appropriate suite**

```bash
vim plugin-eval/suites/basic.json
```

**Step 2: Add test case to `test_cases` array**

```json
{
  "id": "basic-005",
  "name": "My new test",
  "description": "What this tests",
  "tool": "threat_model_generator",
  "input": {
    "system_description": "My test system",
    "scope": "component"
  },
  "assertions": [
    {
      "path": "$.status",
      "operator": "equals",
      "value": "success"
    }
  ],
  "timeout": 15000
}
```

**Step 3: Run the suite to validate**

```bash
npx claude plugin eval run --config eval.config.json --suite suites/basic.json
```

### Creating a New Test Suite

**Step 1: Create new file**

```bash
touch plugin-eval/suites/my-custom-suite.json
```

**Step 2: Define suite structure**

```json
{
  "name": "My Custom Test Suite",
  "version": "1.0.0",
  "description": "What this suite validates",
  "test_cases": [
    {
      "id": "custom-001",
      "name": "First test",
      "tool": "threat_model_generator",
      "input": { "system_description": "Test", "scope": "component" },
      "assertions": []
    }
  ]
}
```

**Step 3: Register in eval.config.json**

```json
{
  "test_suites": [
    "suites/basic.json",
    "suites/my-custom-suite.json"
  ]
}
```

**Step 4: Run it**

```bash
npx claude plugin eval run --config eval.config.json --suite suites/my-custom-suite.json
```

```bash
# Reports are auto-generated in reports/ folder
ls -la plugin-eval/reports/
# Output:
#   basic-report.json
#   threat-report.json
#   security-report.json

```

### View Reports

```bash
# JSON (raw data)
cat plugin-eval/reports/basic-report.json | jq .

# HTML (human-readable)
open plugin-eval/reports/combined-report.html    # macOS
xdg-open plugin-eval/reports/combined-report.html # Linux
start plugin-eval/reports/combined-report.html    # Windows

# Summary
cat plugin-eval/reports/basic-report.json | jq '{total: .total, passed: .passed, failed: .failed}'
# Output: {"total": 4, "passed": 4, "failed": 0}
```

### Generate Custom Report

```bash
# Combine multiple suite results
npx claude plugin eval report \
  --config eval.config.json \
  --input "plugin-eval/reports/*.json" \
  --output plugin-eval/reports/full-report.html

# View it
open plugin-eval/reports/full-report.html
```

### Extract Test Results Programmatically

```bash
# Get pass/fail counts
jq '.passed, .failed' plugin-eval/reports/basic-report.json

# Get failed test IDs
jq '.test_results[] | select(.status == "failed") | .id' plugin-eval/reports/basic-report.json

# Get average duration
jq '.test_results | map(.duration_ms) | add / length' plugin-eval/reports/basic-report.json

# Get all errors
jq '.test_results[] | select(.error != null) | {id: .id, error: .error}' plugin-eval/reports/basic-report.json
```

### Compare Reports Over Time

```bash
# Save baseline
cp plugin-eval/reports/basic-report.json plugin-eval/reports/baseline.json

# Run tests later
npx claude plugin eval run --config eval.config.json

# Compare
diff <(jq '.passed' plugin-eval/reports/baseline.json) \
     <(jq '.passed' plugin-eval/reports/basic-report.json)
```

```
plugin/

├── tests/            ← Unit tests (Jest)
```

**Ownership:** Plugin developers

**Key files:**

| File | Purpose |
|------|---------|
| `src/index.ts` | Tool implementations (what the plugin does) |

| `tests/` | Unit tests for each tool |

**Example commands:**

```bash
npm install        # Install dependencies
npm run build      # Compile TypeScript
npm test           # Run unit tests
```

**What it is:** Framework to test the plugin's accuracy

```
plugin-eval/
```

**Ownership:** QA engineers

**Key files:**

**Example commands:**

## Common Workflows

### Workflow 1: Develop & Test a New Tool

**Step 1: Create tool in plugin**

```bash
# Add to plugin/src/tools/new-tool.ts
export class NewTool {
  generate(input: string) {
    return { status: 'success', result: input };
  }
}
```

**Step 2: Export from index.ts**

```typescript
// plugin/src/index.ts
import { NewTool } from './tools/new-tool';

export async function callNewTool(input: string) {
  const tool = new NewTool();
  return tool.generate(input);
}
```

**Step 3: Declare in plugin.json**

```json
{
  "tools": [
    {
      "name": "new_tool",
      "input_schema": { "type": "object", "properties": { "input": { "type": "string" } } }
    }
  ]
}
```

**Step 4: Add unit test**

```typescript
// plugin/tests/new-tool.test.ts
import { callNewTool } from '../src/index';

test('should call new tool', async () => {
  const result = await callNewTool('test');
  expect(result.status).toBe('success');
});
```

**Step 5: Run unit tests**

```bash
cd plugin && npm test
```

**Step 6: Add integration test in plugin-eval**

```bash
# Add to plugin-eval/suites/basic.json
{
  "id": "basic-006",
  "name": "Test new tool",
  "tool": "new_tool",
  "input": { "input": "test" },
  "assertions": [
    { "path": "$.status", "operator": "equals", "value": "success" }
  ]
}
```

**Step 7: Run eval tests**

```bash
cd plugin-eval && npx claude plugin eval run --config eval.config.json
```

### Workflow 2: Debug a Failing Test

**Step 1: Identify the failure**

```bash
npx claude plugin eval run --config eval.config.json --debug
```

**Step 2: Find the test**

```bash
grep -n "test-id-that-failed" plugin-eval/suites/*.json
```

**Step 3: Review test definition**

```bash
cat plugin-eval/suites/basic.json | jq '.test_cases[] | select(.id == "test-id")'
```

**Step 4: Check actual vs expected**

```bash
cat plugin-eval/reports/basic-report.json | jq '.test_results[] | select(.id == "test-id")'
```

**Step 5: Fix the issue**

- If plugin is wrong: Fix in `plugin/src/`
- If test is wrong: Fix in `plugin-eval/suites/*.json`

**Step 6: Re-run tests**

```bash
npx claude plugin eval run --config eval.config.json --suite suites/basic.json
```

### Workflow 3: Prepare for Production Release

**Step 1: Run full test suite**

```bash
npx claude plugin eval run --config eval.config.json
```

**Step 2: Check all reports**

```bash
# Verify all passed
cat plugin-eval/reports/basic-report.json | jq '.failed'       # Should be 0
cat plugin-eval/reports/threat-report.json | jq '.failed'      # Should be 0
cat plugin-eval/reports/security-report.json | jq '.failed'    # Should be 0
```

**Step 3: Run plugin unit tests**

```bash
cd plugin && npm test
```

**Step 4: Build plugin**

```bash
npm run build && npm run lint
```

**Step 5: Generate release report**


## Troubleshooting

### Issue: "Tool not found"

**Symptom:** `Error: Tool 'threat_model_generator' not found`

**Cause:** Tool is declared in suite but not in plugin.json or not exported

**Fix:**

```bash
# 1. Check plugin.json
cat plugin/plugin.json | jq '.tools[].name'
# Should list: threat_model_generator, security_assessment

# 2. Check export in src/index.ts
grep "export.*generateThreatModel" plugin/src/index.ts
# Should exist

# 3. Rebuild plugin
cd plugin && npm run build

# 4. Re-run tests
cd plugin-eval && npx claude plugin eval run --config eval.config.json
```

### Issue: Tests timeout

**Symptom:** `TIMEOUT: Test exceeded 15000ms`

**Cause:** Plugin takes too long

**Fix:**

```bash
# Increase timeout in eval.config.json
{
```

### Issue: Assertion failures

**Symptom:** `Assertion failed: $.threats length_gte 3 — got 2`

**Cause:** Plugin output doesn't match expected

**Fix:**

```bash
# 1. Debug mode
npx claude plugin eval run --config eval.config.json --debug

# 2. Check actual output
cat plugin-eval/reports/basic-report.json | jq '.test_results[0]'

# 3. Compare to expected
cat plugin-eval/suites/basic.json | jq '.test_cases[0].assertions'

# 4. Update assertion or fix plugin
# Either: Lower expected value in suite
# Or: Fix plugin implementation
```

### Issue: Plugin builds but tests fail

**Symptom:** `npm test` passes but `npx claude plugin eval` fails

**Cause:** Unit tests and eval tests measure different things

**Fix:**

```bash
# Unit tests verify code logic
# Eval tests verify plugin outputs match expectations

# Update eval test to match actual output
cat plugin-eval/reports/basic-report.json | jq '.test_results[].error' # See actual error

# Review and fix plugin implementation or eval test assertions
```

### Issue: Reports folder is empty

**Symptom:** `plugin-eval/reports/` has no files after running tests

**Cause:** Tests may have failed or configuration error

**Fix:**

```bash
# Run with verbose logging
npx claude plugin eval run --config eval.config.json --verbose

# Check eval.config.json
cat plugin-eval/eval.config.json | jq '.reporting'

# Verify output directory exists
mkdir -p plugin-eval/reports

# Try again
npx claude plugin eval run --config eval.config.json
```

## File Quick Reference

### Plugin Files

| File | Contains | Edit when |
|------|----------|-----------|
| `plugin.json` | Tool declarations | Adding new tools, changing signatures |
| `package.json` | Dependencies, build scripts | Upgrading libraries, changing build process |
| `src/index.ts` | Tool implementations | Implementing or fixing tool logic |
| `src/tools/` | Tool-specific code | Adding new tools |
| `tests/` | Unit tests | Adding test coverage |

### Plugin-Eval Files

| File | Contains | Edit when |
|------|----------|-----------|
| `eval.config.json` | Test configuration | Changing timeouts, retries, output format |
| `suites/` | Test case definitions | Adding/removing test cases |
| `fixtures/` | Test data | Sharing test data between suites |
| `reports/` | Test results | (Auto-generated, don't edit) |
